Solution
  • 시안 → 사내 투표 → A/B: 시안은 기존 캡처 1개 + 트렌드 1개(2안), 또는 트렌드 2개를 각각 녹인 3안으로 준비.
    사내 투표로 추린 뒤 YouTube Studio A/B 테스트에 올려 시안별 CTR·시청 시간으로 확정
  • 컨셉 전환: 단순 장면 캡처 → 반전 중심 + 시즌 이슈·트렌드 반영으로 시의성과 클릭 요소를 동시에 강화
  • AI 제작: 캡처로 만들 수 없는 트렌드·감정 이미지는 나노바나나 레퍼런스 생성 → Gemini 비교 → Photoshop 보정으로 제작
  • 검증·최적화: A/B로 시안별 CTR을 비교해 클릭 유도 구성을 반복 개선
  • 자산화: A/B 테스트·CTR 분석을 도입하고 통한 구성을 인수인계 문서로 남김 → 이후 제작자들이 같은 원칙으로 작업
Performance
  • 유튜브 채널 입사 전/후 4개월 비교 기준 CTR 5.7% → 6.0% 상승
  • 수익 $8,500 이상 증가 (월말 정산 확인)
  • 구독자 증가율 약 12% 향상
Roles & Responsibilities

  • YouTube Studio A/B 테스트를 활용해 썸네일별 CTR 및 시청 시간 성과 비교·검증

Failure → Retry

  • 목적: 일상에서도 AI 도구를 직접 파고들며, AI의 작업 흐름을 한눈에 보이게 만드는 실험 공간
Solution
  • 구조 설계: hook 이벤트 → 상태 매핑(state.txt) → AppKit 캐릭터 애니메이션으로 이어지는 파이프라인을 직접 구현. idle/thinking/working/done/notify/sleeping 6가지 상태를 자체 제작 일러스트로 표시
  • 캐릭터 제작: Gemini로 직접 기획·생성(2단계 프롬프트 → 6포즈 시트)하고, Photoroom으로 투명 PNG 처리. Retina 대응 2배 해상도·premultiplied alpha로 작은 크기에서도 선명하게 제작
  • 운영: launchd(LaunchAgent)로 로그인 시 자동 실행·자동 복구, 투명 배경·항상 위 표시, 3분 무활동 시 자동 수면
Lessons Learned
  • 포즈를 추상적인 "상태명"이 아니라 구체적인 동작으로 고정해야 결과가 안정적으로 나옴 — AI 이미지 작업에서 얻은 "빈칸을 줄일수록 재현 가능해진다"는 원칙이 그대로 적용
  • 권한 결정을 앱 팝업과 동기화하려 했으나 한계를 확인하고, "결정은 Claude Code 화면에서, 앱은 알려주기만" 하는 단순한 구조로 되돌림
  • 토큰 사용량 표시는 비교 기준값을 구할 방법이 없어, 틀린 추정치를 보여주기보다 기능 자체를 뺌 — 정확하지 않은 정보는 보여주지 않는 게 맞다고 판단
